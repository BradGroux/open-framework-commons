# Security Policy

Open Framework Commons is documentation-only. It has no application runtime,
deployed service, production dependency tree, or credential store. Security
reports are still appropriate when repository content or project configuration
could expose sensitive information, create a harmful instruction, or compromise
publication integrity.

## Supported versions

The latest published release and the current `main` branch receive corrections.
Immutable older releases remain historical records.

## Reporting

Do not open a public issue containing credentials, private information, or
exploit details. Report sensitive concerns privately through the repository's
[GitHub security advisory form](https://github.com/BradGroux/open-framework-commons/security/advisories/new).

For non-sensitive broken links, factual errors, unclear boundaries, or public
repository configuration, use a normal issue.

Include the affected path or setting, the potential impact, the conditions that
make it relevant, and the smallest safe correction you can identify. The
maintainer will confirm receipt, assess the report, and coordinate disclosure
when a public correction is needed.
