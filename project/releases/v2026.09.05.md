# Open Framework Commons v2026.09.05

- **Release date:** 2026-09-05
- **Type:** Calendar edition; substantive guidance clarifications and repository stewardship
- **Previous release:** [v1.1.0](https://github.com/BradGroux/open-framework-commons/releases/tag/v1.1.0)

## Summary

This edition follows v1.1.0 and introduces calendar versioning. The numbering change alone does not change the guidance. It also resolves the content/process and operational audit backlog through the changes below.

## Guidance and decisions

- Clarified that legitimate help need not be earned, contribution creates no entitlement, openness respects privacy and consent, and responsible stewardship can include closure or disengagement.
- Defined a bounded conflict process: check the adopted revision, pause the disputed action, identify the proper authorities, and record an outcome or an owned deferral with a revisit trigger.
- Required a reasoned applicability and evidence disposition for material shared changes, distinguishing chosen values from claims about effects and preserving counterexamples and uncertainty.
- Defined content compatibility by changes to reader decisions, permissions, responsibilities, scope and authority; made adoption with exceptions explicit.
- Added fictional adverse/ambiguous review cases and [Decision 0002](../../decisions/0002-calendar-editions-and-content-review.md). These illustrate interpretation, not field effectiveness.

## Compatibility

These are substantive clarifications, not merely editorial corrections. A reader who previously treated contribution as an entry condition, openness as disclosure permission, or continuity as a reason to disregard disengagement must reconsider those interpretations. The Commons conflict and review process now asks for more explicit decisions and evidence. Product-local methods and authority remain independent.

The shared scope is still exactly five products. No software runtime, universal workflow, certification, data model or product implementation is introduced. Historical v1.0.0/v1.1.0 tags, notes, decisions and reviews retain their original identities and meaning.

## Adoption

No product adopts this edition automatically. AI-Native, Influence, Relationship and Focus previously recorded v1.1.0 adoption; AI Dev Days retained v1.0.0. Those existing choices remain valid. A product choosing this edition records its exact tag and peeled commit, affected guidance, rationale, authority and any deviations or deferred items. Tooling and release safeguards in this repository need not be copied downstream.

## Repository stewardship

- Replaced ad hoc Markdown regexes with CommonMark parsing and public-inventory link checks, including same-page/reference links and duplicate headings.
- Added isolated regressions and fail-closed tool handling; removed Ruby/ripgrep gate dependencies.
- Validated the active calendar version, real date, release note and complete CFF schema/URL.
- Scanned every publishable file with redacted hygiene and secret checks, including historical reviews and scripts.
- Bound release readback to the explicit Commons repository, checked author and body, and retained historical-version verification.
- Added locked development tooling, CI diagram compilation, dependency updates and a practical release procedure.
- Established release-tag protection, required main validation and immutable future releases, verified separately through GitHub settings.
